## 2. 新增及扩展接口

除公开演示找回入口外，均先校验 JWT、独立会话、空闲有效期及当前角色。错误统一为 {error:{code,message}}，原 message 保留。

| 方法 / 路径 | 角色 | 请求字段 | 成功响应 |
| --- | --- | --- | --- |
| POST /api/passengers | passenger | name、idNumber 必填；idType、passengerType 可选 | 201，{passenger}，仅脱敏身份 |
| PUT /api/passengers/:id | passenger，仅本人 | name/idNumber/idType/passengerType 中要修改的字段 | 200，{passenger} |
| DELETE /api/passengers/:id | passenger，仅本人 | 无 | 204 |
| GET /api/orders/:id/refund-quote | passenger，仅本人已支付订单 | 无 | {quote:{amount,feeRate,feeAmount,refundAmount,rule}} |
| POST /api/auth/change-password | passenger/clerk/admin | oldPassword、newPassword | {requiresLogin:true,message} |
| POST /api/auth/logout | passenger/clerk/admin | 无 | {ok:true} |
| POST /api/auth/reset-password | 公开入口，目标账号必须为 passenger | account、phone、idNumber、newPassword | {requiresLogin:true,message} |
| GET /api/admin/stats?date=YYYY-MM-DD | admin | date 可选，默认北京时间今日 | date、totalOrders、statusCounts、paidAmount、refundAmount、netAmount、topTrains、topRoutes、expiredCleanupCount |
| GET /api/orders（扩展） | passenger，仅本人 | status 可多值逗号分隔；page 默认1；limit 默认20、上限100；keyword | 保留 orders，增加 total/page/limit/hasMore |
| GET /api/orders/all（扩展） | admin | 同上 | 同上，无旅客 userId 限制 |
| POST /api/orders/:id/reschedule（扩展） | passenger，仅本人 | trainId、departureDate、seatType | 保留 {order}；允许跨城，服务器计算补退差 |

GET /api/passengers 保持原路径及 passengers 数组。乘车人 DTO 包含 id、ownerUserId、nameMasked、idType、idNumberMasked、passengerType、createdAt、updatedAt；不输出原始姓名或证件号。

改签原订单重复操作返回 409 / ALREADY_RESCHEDULED；发车退票返回 409 / REFUND_DEPARTED；乘车人数上限返回 409 / PASSENGER_LIMIT。非法日期、页码等为 400；乘车人越权修改/删除为 404。

### 金额与统计口径

- 退票：距发车超过八天免手续费；恰好八天至恰好48小时收5%；恰好24小时至不足48小时收10%；不足24小时收20%；发车时及以后禁止。后端按分舍入，前端不提交金额。
- 统计 date 是北京时间自然日：[当日00:00, 次日00:00)。订单数量按订单创建日及当前状态统计。
- paidAmount 是所选日成功支付流水合计，包括首次购票和改签补款；refundAmount 是成功退款流水合计，包括退票和改签退差；netAmount 为两者差额。不是简单累加现存订单金额。
- Top5 是所选日创建、当前 status=paid 的有效车票数量，按车次或出发城市→到达城市分组；非所有历史售出票次。前端已明确该口径。
- expiredCleanupCount 按实际 cancelledAt 和 timeout 原因计数；手工取消不计入。历史取消记录无法可靠区分原因，不猜测回填。
- 聚合接口只读，不开启事务、不触发清理。并发业务写入时，各聚合查询可能看到略有差异的实时数据，不作为财务对账快照。

## 3. 模型、索引与存量升级

| 模型 | 新增字段或索引 | 兼容方式 |
| --- | --- | --- |
| User | passengerRevision，默认0 | 乘车人写事务用同一用户文档串行化，防并发突破人数限制 |
| Passenger | name、idNumber；唯一索引 {ownerUserId:1,idType:1,idNumber:1} | partialFilterExpression 仅包含 idNumber 为字符串的记录；旧脱敏记录保留并能继续显示，不反推明文 |
| Order | carNumber、seatNumber；passengerIdType、passengerIdNumberMasked | 全部可选；旧单无座位显示“待分配”；新单保存脱敏快照，删除乘车人不影响历史与改签 |
| Order | cancelReason、cancelledAt | 可选；新增手工取消标记 user，超时清理/过期支付标记 timeout |
| Order | {trainId:1,departureDate:1,seatType:1,status:1} | 支持已支付座位查重；不删除 userId/status、status/expiresAt 或既有唯一索引 |
| RefundRecord | feeAmount、feeRate | 可选；旧流水保持不变，新退票写入实际手续费 |

座位规则为 SHA-256(orderId + 席别) 派生起点，在演示编号范围内顺序探测空位。所有出票路径在事务内写同一车次锁，并查已支付座位，冲突时由 Mongo 事务重试；支付重试保留原座位。历史退票/取消不清空座位字段。

正常启动已有 initializeModels 会调用模型 init 创建新增索引，集成测试也在真实临时副本集执行此过程。没有清库、删除历史流水或覆盖历史字段，也没有对全库运行 syncIndexes。原有退款索引兼容迁移继续沿用，未新增破坏性迁移。

若部署环境关闭 autoIndex，需数据库维护者在维护窗口手动创建上表两条索引；在已连接目标数据库的 mongosh 中：

```javascript
db.passengers.createIndex(
  {ownerUserId:1,idType:1,idNumber:1},
  {unique:true,partialFilterExpression:{idNumber:{$type:"string"}}}
)
db.orders.createIndex({trainId:1,departureDate:1,seatType:1,status:1})
```

本轮只在临时库验证，没有连接或迁移现有演示数据库。若原数据库自行导入过重复的明文乘车人证件，新唯一索引会拒绝建立；应先人工核查归属与重复资料，不能自动删历史记录。旧账号缺少 authVersion 的改密兼容已测试；旧乘车人缺少明文证件可在编辑时补充。

找回密码建议先通过注册页创建一个自己知道account/phone/虚构idNumber的演示旅客；不应凭空猜测seed旧记录的原始证件信息。测试改密完成后可再改回演示密码，避免影响后续人工验收。

## 7. 已知限制、未尽事项与文档建议

- 所有支付、退款、实名及找回均为演示功能；三要素找回不能代替正式短信/多因素验证，且当前沿用共享failedAttempts，登录与找回失败次数相互影响。尚未实现公网限流、HTTPS部署、真实支付认证。
- 原始乘车人姓名和证件按本次要求明文落Mongo，只在出参脱敏；生产环境还需完成加密、访问审计、删除策略与合规评估。
- 座位号为确定性演示编号（最多100车×100座/席别），不对应真实列车编组。车次写锁保障一致性，但高并发下会产生重试；本轮未进行性能压测。
- 统计是实时运营视图；不提供多查询一致快照、历史状态回溯或正式财务对账。日期范围聚合未额外新增宽泛索引，大数据量需依据真实查询计划再评估。
- 候补、真实短信/支付、消息队列、多实例共享缓存均未实现。已有站点缓存仍是单进程缓存，各实例各一份，不具备跨实例即时失效保证。
- 未主动修改现有演示数据库，未替用户重启现有服务；实际运行中的旧进程是否已加载新文件需由用户在发布窗口确认。
- 测试运行环境为本机现有Node.js v24；未另行在Node.js20容器、Safari或macOS实机重复认证。
- 建议将README中的功能、费率、跨城改签及测试数量更新到本次实现，并将TEST_REPORT补充为新增版本；按用户约束，本次两文件均保持原样，建议仅记录于此。
